# هویت پایدار و غیرمعنایی

entityهای داخلی workflow شناسه‌های opaque و پایدار دارند و Canonical Financial Event از شناسهٔ غیرمعناییِ پایدار مانند FE-000001 استفاده می‌کند. عنوان فارسی، alias، کد legacy/منبع، نام زیرسامانه، رابطهٔ مرکز هزینه و status lifecycle کلید identity نیستند؛ rename identity را تغییر نمی‌دهد. split/merge معنایی identityهای canonical جدید با lineage صریح می‌سازد، شناسه‌های superseded برای تاریخچه رزرو می‌مانند و هرگز reuse نمی‌شوند؛ entityهای versioned نیز identity منطقی پایدار را از identity immutable نسخه جدا می‌کنند.
